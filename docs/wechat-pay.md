# 微信支付接入与部署

本项目接入普通商户的小程序支付 API v3。客户支付服务订单及曝光费用后，款项进入所配置微信支付商户的收款体系，按照商户平台的结算设置结算到绑定银行卡。支付成功与银行卡结算到账是两个状态。本次不接入收付通、工程师入驻、分账或工程师提现；现有模拟钱包仍为模拟功能。

用户提供的 [JSAPI 产品介绍](https://pay.weixin.qq.com/doc/v3/merchant/4012062524) 是公众号网页支付介绍。小程序采用同一 JSAPI 下单接口，前端使用 `wx.requestPayment`，见 [小程序下单](https://pay.wechatpay.cn/doc/v3/merchant/4012791897) 和 [小程序调起支付](https://pay.wechatpay.cn/doc/v3/merchant/4012791898)。

## 上线配置

1. 在微信支付商户平台开通普通商户的小程序支付，关联项目实际使用的小程序 AppID，并确认该 AppID 支付权限正常。交易类小程序还需按微信公众平台要求接入订单发货管理；当前项目中的交付附件功能不等同于微信的发货报备。是否适用及开通情况在公众平台核对，未满足可能无法调起正式支付，参见 [官方调起支付说明](https://pay.wechatpay.cn/doc/v3/merchant/4012791898)。
2. 商户平台 → 账户中心 → API安全：申请商户 API 证书，保留 `apiclient_key.pem` 私钥和证书序列号；设置32字节 APIv3 密钥；申请并下载微信支付公钥，记录 `PUB_KEY_ID_...` 公钥 ID。本实现使用微信支付公钥模式，公钥必须对应该 ID。商户证书序列号、微信支付公钥 ID、APIv3 密钥、小程序 AppSecret 是不同参数。参见 [证书密钥概览](https://pay.wechatpay.cn/doc/v3/merchant/4024350132)。
3. 在云托管的服务端环境变量/密钥管理中设置下面的参数。私钥不能放在小程序、Git仓库、截图或聊天消息中。

```dotenv
NODE_ENV=production
PAYMENT_MODE=wechat
WXPAY_TRANSPORT=v3
WX_APPID=实际小程序AppID
WXPAY_MCHID=实际普通商户号
WXPAY_SERIAL_NO=商户API证书序列号
WXPAY_API_V3_KEY=商户平台配置的32字节APIv3密钥
WXPAY_PRIVATE_KEY_BASE64=完整apiclient_key.pem文件的Base64
WXPAY_PUBLIC_KEY_ID=PUB_KEY_ID_实际微信支付公钥ID
WXPAY_PUBLIC_KEY_BASE64=完整微信支付公钥PEM文件的Base64
WXPAY_NOTIFY_BASE_URL=https://实际云托管公网域名
PAY_AMOUNT_OVERRIDE_FEN=
PAY_TIMEOUT_SEC=1800
```

有密钥文件挂载能力时，可设置 `WXPAY_PRIVATE_KEY_PATH`、`WXPAY_PUBLIC_KEY_PATH`，并将两个 Base64 变量留空。云托管没有挂载能力时使用 Base64 环境变量；Base64 只是编码，仍属于敏感密钥。可在本机 PowerShell 中使用 `[Convert]::ToBase64String([IO.File]::ReadAllBytes('实际文件路径'))` 编码完整文件，将结果只填入服务端密钥配置。服务端缺少配置时拒绝发起微信收款，不会降级成模拟付款。商户密钥轮换后重启服务；更换商户号或 AppID 前须处理完原商户的待支付和待退款记录，新单保存的商户快照会阻止用错误商户关单或退款。

4. 云托管必须提供公网 HTTPS 域名。`WXPAY_NOTIFY_BASE_URL` 只填域名，不附 `/api`、参数或账号密码。开放下面三个路由供微信直接访问，不能要求微信携带小程序登录凭证；其身份由微信支付签名校验。转发时保留 `Wechatpay-*` 请求头及原始 JSON 字节，不能改写通知体。

| 用途 | 公网回调路径 |
| --- | --- |
| 服务订单付款 | `/api/pay/v3/notify` |
| 曝光付款 | `/api/exposure-pay/v3/notify` |
| 原路退款结果 | `/api/pay/v3/refund-notify` |

这些地址由服务端在下单、退款时传给微信。处理成功返回 HTTP 204；验签、解密或查单失败返回失败状态，允许微信重试。旧云托管回调路径继续兼容历史单，不接受新 v3 单的未签名通知。

5. 部署服务端及小程序；数据库启动迁移会添加支付通道、商户快照和退款表，也可以先在 `server` 目录执行 `npm run migrate`。迁移需要数据库建表/改表权限。历史支付、曝光记录默认标记为 `cloudbase`，不要批量改成 `v3`。旧支付单的查询和取消仍需要原云托管开放接口、原商户及回调服务配置。

## 已实现行为

- 服务订单和曝光购买：HTTPS 直连官方接口，RSA 请求签名、响应验签、小程序 RSA 支付参数；商户支付单号使用现有随机唯一编号，不超过32位。支付结果由服务端查单确认，前端支付弹窗成功不直接把订单改为已支付。
- 回调：原始报文 RSA 验签、5分钟时间戳窗口、公钥 ID 校验、AES-256-GCM 解密，并校验商户、AppID、事件类型和通道；查单确认金额、币种和交易流水后幂等落账。实现依据 [签名验签规则](https://pay.wechatpay.cn/doc/v3/merchant/4012365342) 和 [通知解密规则](https://pay.wechatpay.cn/doc/v3/merchant/4012071382)。微信 HTTP 错误响应可能无签名，与官方 SDK 一致仅强制验证2xx；任何带签名的响应仍必须验签。网络失败不能视为已支付或已关单。
- 仿真币：100币抵扣1元，只向微信收取现金差额；全币支付不创建0元微信交易。取消或超时须先查单并关单，再释放冻结仿真币。
- 原路退款：工程师同意退款或管理员裁定退款后，对 v3 支付单创建唯一退款单，自动提交和查单。现金按原支付现金与抵扣比例退回，不超过原实收；确认微信退款成功后才返币。全币退款直接返币，不调用0元退款接口。退款来源和单号固定，网络超时及多实例重试不会创建第二笔退款，参见 [退款申请](https://pay.wechatpay.cn/doc/v3/merchant/4012791903)。
- 退款后台任务每30秒运行，发现已批准申请；已提交退款每分钟查单补偿通知丢失。异常/关闭退款保留实际状态，需在商户平台核对处理。管理员的“已处理退款”操作对 v3 单改为发起/查询真实退款，不能手填交易号伪造成功。订单双方可在详情顶部看到现金退款与返币进度。
- 曝光付费属于平台自营曝光服务，收款成功后启用原有推流。曝光购买退款仍需人工通过商户平台处理，不包含在服务订单退款中。

## 上线验收

本地测试使用临时生成的 RSA 密钥及模拟的官方响应验证请求/响应签名、通知解密、伪造回调拒绝、通道隔离、并发退款、部分退款尾差及返币幂等，不连接真实商户。没有商户配置时不能完成真实付款或银行卡到账验证。

配置并部署后，使用正式 AppID、真实微信用户依次验证：服务订单收款、曝光收款、混合抵扣、全币支付、取消/超时关单、通知延迟后的主动查单、工程师同意退款、纠纷部分退款。核对商户平台支付/退款记录与本地 `payments`、`order_exposures`、`payment_refunds`，并检查银行卡结算状态。首次真实联调可创建实际报价为小额的订单；生产必须关闭一分钱覆盖价，不能修改真实订单金额进行验收。
