# 逾期提醒与48小时违约登记

## 已实现

- 订单双方详情显示实际逾期时长、截止时间、延期状态。客户可以催单或进入原有退款/纠纷入口，工程师可以提交延期。
- 自动逾期提醒与客户催单写入订单会话；同一订单、同一截止时间各提醒一次。不是微信订阅消息或短信送达承诺。
- 无待审批延期且逾期满48小时未交付，生成全額待退款记录。延期被拒不重置截止时间；同意才延长。待审批期间暂停自动判定，不代表截止时间暂停。
- 自动判定将订单关闭，并在纠纷管理中生成已判定/待退款记录，说明标记为系统逾期判定。订单双方可查看记录，管理员在纠纷详情核实后登记实际退款结果。
- 不调用真实退款通道，不扣模拟钱包余额；信用分与完单率自动考核尚未启用，不在页面虚构已扣分。

## 资金保护

订单必须仍在进行中、有匹配成交金额的成功支付记录、未交付、没有进行中或已处理退款等冲突记录。订单锁串行判定，delivery_breaches 以订单ID唯一，消息、判定和待退款记录同事务提交。金额为订单成交总额，不叠加额外赔偿。

## 部署与验收

先完整部署后端，再编译小程序。启动迁移新增 delivery_reminders 与 delivery_breaches。启动后自动扫描、此后每分钟扫描；容器停止期间不运行，恢复后补扫。订单详情读取也会检查。

注意：扫描包含符合条件的历史订单。上线前应先核查历史付款时间、成交工期、订单状态和已有退款登记，避免错误旧数据触发新规则。未执行生产部署或修改生产数据。

1. 隔离测试库将截止时间设为6小时前，双方看到逾期；客户重复催单只写一条催单消息。
2. 改为49小时前但保留待审批延期，不生成违约；拒绝该延期后，下一次检查按原截止时间生成待退款。
3. 同意延期，使用新的截止时间；交付完成、已有退款/纠纷或无成功支付凭证均不得自动重复退款。
4. 重启服务、多实例重复扫描，同一订单只生成一条违约及待退款。管理员查看“纠纷管理→全部/已结案”中的待退款记录。
5. 管理员登记不实际调用支付服务。只有核对真实资金结果后才能填写真实流水并登记已退款。
