# 模拟钱包、卡券、签到与成就

## 部署

先完整提交项目并部署后端，再重新编译小程序。后端启动时，community-migration 自动创建 8 张新表；已有订单、支付、奖励记录不重建。控制台备用建表文件为 community-features-schema.sql，控制台不支持多语句时需逐条执行。

钱包是 demo_* 独立模拟账本，与订单收入和支付金额完全隔离。当前没有真实提现通道、完整银行卡采集、银行鉴权、短信认证或资金划拨代码。不是把生产支付配置切换后就能启用真实打款。

## 已实现

- 工程师不能新增自收藏，历史自收藏从列表隐藏。
- 合作页说明工程师自行让利；客户主页标记工程师让利。首单折扣仍须体现在工程师报价中，不重复修改支付金额。
- 双方每日签到：北京时间自然日，每账号每日8币，唯一业务键防止重复发放。签到与连续完成订单是两种独立进度。
- 激励中心按原型的概览、排行、连续挑战、成就网格、任务列表排列；统计真实完成订单，不填充原型示例数字。客户按自己的订单统计，工程师按承接订单统计。
- 成就奖励领取后，可选择展示到工程师主页。后端校验归属及获得记录，不能凭客户端参数解锁。
- 卡券与仿真币：活动领取、余额、明细与卡券有效期。新人券50元（满1000元），首单任务券30元（客户发布需求/工程师完成订单后领取），仿真币体验礼包20币；每账号每项限领一次。卡券90天有效，当前均为待启用抵扣权益。
- 既有任务奖励统一纳入仿真币余额，不二次迁移发放。暂不抵扣、提现或转让；分享行为本身不发邀请奖励。
- 模拟钱包：可用/冻结余额、追加式变动账本、冻结记录、银行卡测试尾号、提现单及状态事件。

## 模拟提现验收

1. 工程师打开“我的→钱包、提现及银行卡绑定”，确认初始余额0，不从收益看板自动入账。
2. 绑定“测试银行/0001”。只接收4位测试尾号；不能提交真实姓名、手机号或完整卡号。
3. 超级管理员进入“模拟钱包与提现”，输入工程师用户ID、100元及入账说明。重试同一个业务编号不应再次入账。
4. 工程师申请提现40元：可用60元，冻结40元，账本与冻结记录各有对应记录。重复请求不能重复扣款。
5. 管理员依次“审核通过→进入模拟打款→模拟打款成功”：可用60元、冻结0；用户看到“模拟已打款（非真实到账）”。
6. 再申请20元，选择拒绝/用户撤销/模拟打款失败，相应冻结额回到可用余额。已完成状态不能反向修改。
7. 无足够余额时申请失败；处理中不能换绑或解绑；普通客户不能访问钱包，非超级管理员不能处理模拟入账或审核。
8. “处理记录”与管理操作审计保留每次状态变更。所有模拟操作不调用真实支付服务。模拟余额或冻结尚未清空时，会阻止账号注销。

## 前端验收

1. 客户首页首个快捷入口是每日签到，底部中央“+”进入发布需求，仍保留实名认证要求。
2. 工程师首页的签到浮窗可拖拽并保存位置；拖动结束不应误跳转；不遮挡底部导航。
3. 同一天重复签到，只增加8币，两个角色都可查看签到记录。
4. 任务未完成不能领奖；领取后可展示徽章，另一账号打开工程师主页可见；取消展示后刷新不再显示。
5. 同一活动重复领取不增加卡券或币。客户端无法自定奖励金额。

## 真正上线资金业务前

需单独设计并验收真实结算入账、退款/争议冻结、费用与税务口径、银行鉴权与敏感信息保护、签名回调、通道幂等、异步失败与对账补偿、限额风控及审计权限。本次未接这些外部服务，也未修改现有支付扣款逻辑。
