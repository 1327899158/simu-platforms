# 运营分析

入口：管理员工作台 → 运营分析。查看需 DASHBOARD_READ，订单异常明细及工程师质量需 ORDER_READ，保存措施需 CONFIG_MANAGE。

## 已接入

- 近7/30/90天滚动统计、上一个等长窗口、每日发布趋势、六阶段漏斗。
- 领域需求、报价覆盖、完成、退款及纠纷订单数，当前有效认证供给。
- 全时间异常队列：发布48小时未选/无报价、选定24小时未支付、纠纷7天未结束。逾期履约按当前延期条款或付款时间加报价工期判断，各队列最多50条，不代表全部异常数量。
- 新注册客户发布/支付转化、30/60/90天成熟首次支付客户复购、连续两期报价工程师数。
- 本期评价均分和低分率、按本期选定订单数前20名的工程师退款及纠纷统计。
- 推广方式的需求数、累计浏览、报价覆盖与支付订单数。
- 客服首次人工回复平均耗时和已回复样本、当期未解决与全历史积压、问题分类。
- 复用财务中心现有支付、发票、推广标价和模拟提现报表。
- 优化措施名称、执行日期和目标保存到已有 admin_console_settings 的 operationsPlans，最多100项，保存和审计在同一事务中。

## 统计口径

所有窗口服务端UTC计算，页面日期趋势按北京时间分组。公开需求按创建时间归入固定样本，统计截至当前进展，包含后来关闭/删除记录，排除定向需求。历史报价若被删除无法还原。相邻时期订单成熟程度不同，不能直接用于证明干预效果。无分母显示“—”。领域标签去重，但多方向订单可出现在多个领域中。

客户复购为全历史第一次支付后指定天数内至少两笔不同订单支付；观察期未满的客户不入分母，含定向订单及模拟支付。工程师质量按选定时间归组，含定向订单、显示样本量，未完成订单并不等于失败。

推广累计浏览不是曝光次数，且不是所选期间内发生的浏览；分组对比不是因果效果。退款申请不等于退款已到账。首响只计算首次STAFF回复，排除SYSTEM消息；未回复的会话不进入平均值但保留在数量中。在线会话可能被重新使用，此指标不是每轮咨询的响应时长。

## 前端待接入区

页面登录/访问留存、取消/未成交结构化原因、推广曝光和点击率、推广实际收益率、客服满意度、精确解决耗时、真实佣金/手续费/补贴/利润、自动实验归因。无模拟结果冒充真实指标。

## 发布和验证

无需新增数据表，复用已有迁移创建的配置表。部署后端并更新小程序管理端。自动测试覆盖统计窗口、分母、标签去重、权限、明细截断、复购观察期查询、当前延期查询，以及措施日期校验、审计失败回滚和数量上限；未连接线上MySQL进行查询性能或真实数据核对。首次发布需按真实订单抽样核对，并在数据量增大时检查执行计划及索引。
