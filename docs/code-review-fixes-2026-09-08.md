## 已修正

| 模块 | 问题与处理 |
| --- | --- |
| 认证 | 微信新建工程师资料存在无论环境都填 APPROVED 的分支。所有注册/新增工程师资料统一 PENDING；生产环境强制关闭自核验。保留已有审核结果，不批量修改历史用户。 |
| 报价/选标 | 固定预算订单可通过 PATCH 修改金额；报价修改、撤回、选标之间缺少一致锁顺序。现在统一先锁订单，再读/锁报价，事务内重新验证状态；固定预算禁止变价。 |
| 交付/验收 | 无文件、不存在文件、他人文件、跨订单文件也可能推进交付；更新文件未同步关系表。现在至少一个有效成果文件，校验归属及业务用途，并原子写入 RESULT 关联。交付/验收/驳回后的通知失败不再把已成功操作报告为失败（通知失败记录日志，未新增持久化重试队列）。 |
| 文件 API | 无订单图片泛化为公开图片，纠纷证据拒绝后仍可能落入公开分支。现在优先检查私有用途，只有实际头像引用可公开；限制文件登记用户目录；聊天/认证/发票防止私有文件跨业务复用；已发送聊天文件和已提交证据不能直接删除。详见下面的云存储边界，API 修复不等于云对象已私有。 |
| 支付 | 原代码把 V3 transactions 路径拼到云托管支付网关；修正为 unifiedorder/queryorder/closeorder，提取 payment 调起参数。回调只触发服务端查单，校验商户、AppID、交易号、金额和币种，不信任请求体声称的成功。失败返回失败以允许重试；前端支付轮询可主动查单。 |
| 支付状态 | 新支付单号控制在 32 字符内；订单锁内复用 PENDING 支付单；生产忽略一分钱覆盖价；超时先查单/关单，再在锁内确认没有新支付单才回退。过期支付单迟到成功只记录收款异常，不推进重新选标后的订单。 |
| 客户评价 | 修正金额未格式化、标签返回 JSON 字符串、已有评价仍走 POST 的问题。首评/修改共用订单状态、选中工程师、唯一评价及最多修改一次校验；验证评分和标签。移除尚未实现的“自动信用分/提醒其他工程师”的界面承诺，保留内部治理记录。 |
| 客户发票 | 原列表最多 100 笔导致旧订单遗漏，汇总随截断失真；批量无选择且可能超过后端 50 笔限制。现在服务端筛选分页、独立全量汇总；批量明确选择本批最多 50 笔并防重复点击；订单详情和开票详情分开跳转；去掉“已发送邮箱”的不实提示。 |
| 平台发票 | 工程师不能再把 PLATFORM_REQUESTED 直接标成 ISSUED。新增管理员上传并交付已实际开具的文件，要求 INVOICE_PROCESS 权限，并在同一事务写审计。当前仅超级管理员的通配权限包含此新能力，未扩大普通运营/审核员权限。 |

支付接口路径与请求结构核对了 [微信云托管官方支付示例](https://github.com/WeixinCloud/wxcloudrun-pay-nodejs/blob/master/server/index.js)。没有进行真实商户联调；不能据此认定当前云环境已具备该接口能力。

## 联调验收步骤

使用独立测试环境和测试账号：客户 C、通过认证的工程师 E、另一工程师 E2、超级管理员 A。

1. 新账号认证：分别用微信、手机号、密码注册工程师，尚未提交审核时不能显示为已认证或直接报价；生产配置即使误设 ALLOW_ENGINEER_SELF_VERIFY=true 也不能自核验通过。核对历史异常审核数据，不要直接批量降级已正常审核用户。
2. 报价：C 发布固定预算 3800 元的需求，E 报价；PATCH 报价金额为 4000 元应返回 409。E 修改/撤回报价与 C 选标同时操作，只允许一个符合当前状态的结果，不应出现选中已撤回报价或金额不同步。
3. 交付：对已支付订单提交空数组、不存在的文件、E2 的文件、另一订单的文件，应失败且订单仍为执行中。E 正常上传成果交付后，C 的成果列表应能查看文件。模拟通知服务异常，不应重复交付才能成功。
4. 客户评价：未完成订单不能评价；完成后 E 能评价 C、显示 ¥3800.00、选择标签并保存；再次进入加载已有评价，最多修改一次。E2 和客户本人不能通过工程师入口取得该私有评价。
5. 发票：用超过 100 笔已完成测试订单核对汇总、筛选及上拉加载。批量弹窗取消部分勾选，仅选中项生成申请；连续点击不重复提交。已开票只能提示实际可下载文件，不提示已发邮件。
6. 发票交付：E 选择自行开票后上传文件，C 可下载；E 选择平台协助后不能自行标记完成。A 在管理端上传实际发票后状态变为已开票且产生审计记录；只读审核员不可提交。这个操作不代替税务系统实际开票。
7. 模拟支付：保持 PAYMENT_MODE=mock，完成下单、支付、验收；伪造公开成功回调不能推进订单。
8. 真实支付（单独准备商户联调环境）：核对 WXPAY_MCHID、WX_APPID、云调用商户授权和 WXPAY_CALLBACK_SERVICE（如 simu-api）。后者未设时读取平台 X-WX-SERVICE；旧 WXPAY_NOTIFY_URL 不再使用。验证返回 payment 参数、真实查单确认、通知延迟轮询确认、关单失败不回退、关单成功才回退。生产环境不会使用 PAY_AMOUNT_OVERRIDE_FEN；请用非生产专用低额测试订单，不要误扣正式订单金额。
9. 文件权限：用无关账号访问已知内部文件 ID 的 `/api/files/:id/url` 应返回 403；再直接用已知 cloud fileID 测试云存储。后者在当前示例规则下仍可能成功，必须按下一节完成存储授权改造才可视为安全验收通过。

## 尚未解决／需部署配合的边界

- **高优先级：云存储直读权限。** `docs/cloud-storage.rules.json` 的 read 为 auth != null，绕过后端直读已知 fileID 仍有风险。需要私有存储 + 后端短期签名下载，或云端逐文件授权，并同步改造订单、聊天、头像和管理员材料下载。本次没有擅自调整线上规则；单独收紧为创建者可读会中断现有跨用户下载。部署文档已补充警示。
- **真实支付/退款不是已完成的线上验收。** 当前保留 mock 模式；真实支付依赖微信云托管网关及商户授权。退款、人工对账仍需既有业务处理，迟到收款记录为 SUCCESS 并附 ORDER_NOT_AWAITING_PAYMENT 异常，不自动退款或把钱应用到新工程师。上线前须人工核对这类记录和旧的一分钱支付单。
- **平台开票是申请与文件交付，不是税务开票 API。** 企业资质自动判定、个人订单自动代开、税务自动开具、邮件发送和服务费结算未接入，不能通过改状态替代真实开票。优惠券、仿真币保持规则/接口预留，不改变支付。
- **规模风险。** 推荐工程师列表仍遍历工程师并逐个聚合/持久化等级，数据增长后需改为批量聚合/缓存并压测；当前未进行大规模性能验证。现有等级的累计完成/纠纷统计口径未擅自变更。
- **密钥与历史数据。** 本次未轮换用户曾粘贴的密码/密钥，也未重写历史审核、支付和发票数据。已暴露有效凭据需要在对应平台轮换；身份数据加密密钥不可直接替换，否则旧密文无法解密，应先制定重加密迁移。
