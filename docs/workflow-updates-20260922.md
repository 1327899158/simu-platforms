# 资料、聊天与售后交互调整（2026-09-22）

## 功能

- 发布需求、成果交付、退款附件、纠纷材料、身份认证补充材料、工程师和管理员发票交付入口支持网盘分享链接及提取码。图片专用入口保留原方式。提示用户保持分享有效、填写提取码而非网盘登录密码。
- 网盘资料使用原有附件关联和权限检查；链接、提取码在通过读取权限检查后返回。查看时可复制链接和提取码，进入相应网盘查看，平台不代为保存网盘中的文件。
- 聊天输入区固定在页面底部，根据键盘高度调整位置；进入会话读取最新100条，向上滚动加载旧消息。聊天文件入口限制单个文件不超过1MiB，前后端均校验大小。
- 查看工程师资料直接跳转完整资料页；客户资料直接在资料页展示。
- 每个订单最多提交3次退款申请，拒绝后可再次申请，未处理申请不能重复提交；达到3次后只能走客服介入。提供退款原因选项，“其他”需填写说明。已有申请计入次数。
- 发票申请支持增值税普通发票、增值税专用发票；单位抬头要求税号，专票不支持个人消费者。传统专票要求地址、电话、开户行和账号，数电形式这些字段选填。单笔和批量入口统一验证，工程师及管理端可查看资料。
- 纠纷双方可读取对方证据，包括带订单关联的证据。通过业务授权后为云文件提供短期签名地址；证据成功入库时在同一事务写入订单会话通知，提交方不会产生自己的未读提示。详情页打开时每10秒刷新材料。
- 客服工单详情改为聊天气泡、固定输入区，客户和管理员打开页面时每2秒同步消息，离开后停止轮询。发送成功立即刷新会话；保留关联订单、截图、受理及关闭等操作。这是前台轮询，不是后台微信订阅消息通知。

## 订单号机制（本次只核查，未更换算法）

实现位置：`server/src/db.js` 的 `nextOrderNo()`。

格式为 `SIM + UTC日期YYYYMMDD + 8位随机十六进制字符`，例如 `SIM20260922A19C72EF`。随机部分来自 `crypto.randomBytes(4)`，并非按时间戳递增；同一时刻创建不会必然生成相同号码。

生成时最多尝试5个候选号码，逐一查重。数据库 `orders.orderNo` 有唯一索引，防止重复号码入库。随机候选存在理论碰撞可能；并发创建时两个请求也可能在插入前都查到“不存在”，随后其中一个被唯一索引拒绝。目前没有针对这类插入冲突的自动重试，因此不能承诺每次创建都成功，但不会保存两个相同的订单号。

## 发票字段依据

- 国家税务总局：[企业购买方申请普通发票应提供纳税人识别号](https://www.chinatax.gov.cn/chinatax/n810214/n810641/n2985871/n2985888/n2985983/c2990837/content.html)。
- 上海税务：[增值税专用发票开具所需购买方资料](https://shanghai.chinatax.gov.cn/bsfw/zpkjzn/node2/201705/t432085.html)。
- 宁夏税务：[数电发票票面简化，取消地址、电话、开户行及账号等栏次](https://ningxia.chinatax.gov.cn/art/2023/6/15/art_10996_304365.html)。

此处用于收集开票申请资料，实际开票仍由工程师或平台处理。

## 发布及验证

1. 发布后端。启动迁移会补充 `uploaded_files.netdiskUrl`、`uploaded_files.netdiskPassword`、`invoice_requests.invoiceDetails`，部署账号需有增量建表字段权限。
2. 编译并发布小程序，前后端应配套更新。
3. 使用客户、工程师、客服三个账号验证：网盘需求/交付及读取；退款拒绝后的第2、3次申请及第4次阻止；专票/普票申请；对方证据下载及未读提示；客服互发消息。
4. Android、iOS真机检查聊天进入后位置、键盘展开/收起、历史翻页、1MiB文件发送及超限拒绝。
