# 私密图片直传上线步骤

适用：客服截图、反馈/举报图片、企业资质。新图单张5MB，支持JPEG/PNG。请求不传图片Base64。

## 必须按顺序上线

1. 后端先部署新代码，暂不启用 `PRIVATE_STORAGE_ENABLED`（默认关闭）。自动建立 private_upload_tasks；不修改或删除旧加密图片。
2. 先部署后端并发布适配后的小程序，再进入当前 CloudBase 环境的云存储 → 权限设置。备份线上原规则，选择内置的“仅创建者及管理员可读写”。本方案不使用路径正则，停止使用旧的 `docs/cloud-storage.rules.json`。`docs/cloud-storage.owner-only.rules.json` 仅供核对微信身份规则，优先使用控制台内置选项。仓库文件不会自动发布到云端。
3. 该权限影响整个存储桶，不只是私密目录。附件通过后端业务鉴权后签发下载地址；案例预览、聊天图片和已登记头像同样走授权接口。先在维护窗口以测试账号验证。未在 uploaded_files 登记的历史云头像需另行核对，不能为了兼容而开放任意 fileID 签名。旧客户端可能无法查看对方文件，不宜长时间与旧版并用。
4. 用非敏感测试图验证：创建者可读写自己的临时图片，另一个微信身份不能直接读取；服务端创建的正式归档本人及其他客户端均不能直接读取、覆盖、删除。只允许通过业务预览接口查看正式归档。确认普通订单附件双方、聊天双方、案例浏览、头像和管理员审核均正常。若不符合，保持功能开关关闭，不上传真实资料。
5. 确认上述测试通过，在后端设置 `PRIVATE_STORAGE_ENABLED=true` 并重新部署。最后编译、预览小程序，进行下面的完整验收。不要在权限未验证时开启。

## 流程和权限

- 前端获取当前业务账号的上传任务，路径由服务端生成，并带可信微信身份。使用 wx.cloud.uploadFile 上传到临时私密目录。
- 用户可以微信、手机号或账号密码登录，但文件归属按后端会话中的 userId 校验，不按前端传来的用户ID、不只按微信OpenID。
- 注意：云存储创建者按微信身份区分，不按业务登录账号区分。同一个微信切换A/B业务账号，仍可能直接访问该微信上传的临时对象；正式证据由服务端另存并控制权限。此方案不是临时对象的业务账号级隔离，不能把临时文件当作已归档证据。
- 上传后仅提交 taskId 与 fileID。任务15分钟有效；服务端检查归属、用途、精确文件ID、实际大小和文件头，限时读取不超过5MB。
- 服务端把校验过的字节写到由服务端创建的随机正式路径（不同于客户端已知任务ID），数据库记录云文件引用。客户端不能预知路径提前占用创建者身份。上线必须实测归档对象创建者权限；即使上传者修改临时对象，也不应改变已提交材料。确认接口可安全重复调用。
- 本人或授权管理员通过原有查看接口获取临时HTTPS地址。地址有效期内属于访问凭证，不记录到日志、不长期缓存。请求SDK maxAge为300秒，具体链接有效期需以当前环境存储策略实测为准。
- 旧数据库加密记录继续解密读取，新记录返回临时链接。不需要搬迁历史资料。
- 临时对象在创建24小时后由每小时任务清理；未成功确认的正式目录孤儿同时清理。若云端未确认删除，记录不会标为清理成功，将重试。已确认图片即使尚未绑定工单，也暂保留，不自动删除证据。
- 当前新图是私密云对象，不使用旧图片的应用层AES密钥加密；请在控制台另行核实静态加密与备份设置。目录访问控制不等同于应用层加密。

## 验收

1. 手机号账号A上传大于100KB、小于5MB的截图，提交客服工单成功；后台客服可查看；也测试反馈/举报、企业资质及旧图片。
2. 同一微信退出A，登录账号B：通过查看API、冒用任务、替换文件ID均不能读写A的资料。
3. 普通账号不能调用管理端预览；管理员必须具有对应审核/客服权限。
4. 重复确认同一任务只生成一条资料；过期任务、伪造文件ID、超过5MB及非JPEG/PNG应被拒绝。
5. 企业审核提交后尝试覆盖临时图，正式审核图片不得变化；客户端不能覆盖正式路径。
6. 断网后重试、取消选图、图片预览地址过期重新进入页面、临时对象清理重试均正常。

本地测试使用模拟云存储，不能证明线上规则已正确发布。上述云端配置与真机权限验收是启用前的必要步骤。
