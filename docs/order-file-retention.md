# 订单文件定时清理

后端部署后自动建表并启动每小时扫描，启动时也扫描。只处理已完成订单的需求附件和交付成果，不清理头像、案例、企业资质等其他资料。

- 完成后至少保留90天；进入最后7天发送系统消息，最后1天再次提醒。停机错过提醒则延后删除，确保通知后完整保留7天和1天。
- 历史订单首次扫描起至少再保留7天，不立即删除。
- 系统提醒写入客户与接单工程师的订单会话，不是微信订阅消息；未打开小程序的用户不会收到外部短信。
- 未结束纠纷、待处理退款暂停清理。客服工单尚无订单关联，因此双方有未关闭工单时保守暂停。恢复后重新走提醒期。
- 其他业务引用（包括聊天附件、案例、证据、认证、头像和相同云对象的其他文件记录）全部保留。
- 清理保留 uploaded_files 和 order_attachments 元数据，file_cleanup_log 记录文件、订单、云对象和清理时间。下载入口显示已到期清理。
- 每个订单每次最多清理一个文件，避免批次中途失败回滚此前成功记录。云端失败不会记录成功，会重试；云端删除与MySQL不是分布式事务，云端成功后数据库故障需要结合日志核对，不能仅看数据库确认云端是否存在。

## 验收（仅独立测试环境）

1. 创建真实测试文件及已支付、已验收测试订单。将该测试订单 completedAt 调整到100天前，重启测试后端，检查订单会话出现7天通知、云文件仍存在。
2. 重启或重复扫描，不得重复发送同一提醒。生产请勿通过改时间加速清理。
3. 单元测试通过模拟时间检查最后1天提醒和删除，不需要等待90天。运行 `node --test server/test/file-retention.test.js`，不会连接云存储或真实数据库。
4. 测试环境中模拟未结纠纷、退款、客服工单及文件被案例/聊天引用，确认不删除。清理接口失败时不得生成成功记录。
5. 在测试环境验证实际云存储删除权限及SDK响应，清理成功后应保留文件名、显示已到期清理，下载接口不再返回可下载地址。

物理删除不可依赖应用恢复；如需可恢复性，应另行配置独立备份。当前任务没有访问或删除线上文件。
