# 管理端改造说明（2026-09-24）

参考文件：`F:/UI-仿真服务平台-折叠页面导航版.html`。该文件包含整个平台原型，管理端约 25 个页面。本次改造对象为**现有小程序 admin 分包**，没有新建电脑网页后台。

## 页面与功能对应

| 原型模块 | 实际入口与处理方式 |
| --- | --- |
| 管理首页 | 工作台：管理员身份、实际待办角标、优先处理、四项业务指标、折叠功能分组、底部导航。菜单依真实权限显示 |
| 认证列表 / 详情 | 复用身份认证列表与用户/工程师详情；企业、机构、毕业院校认证保留独立入口及管理员指定标签 |
| 纠纷列表 / 详情 | 复用举证、消息和裁决流程，不照搬原型示例责任判定 |
| 举报列表 / 详情 | 复用举报与反馈处理流程 |
| 系统判定申诉列表 / 详情 | 新增退款申诉清单，仅列已关联纠纷的真实退款请求，进入现有仲裁详情；信用扣分申诉尚未接入 |
| 数据看板 | 复用近七日趋势、订单与认证分布、评价统计；工作台新增北京时间今日订单、成功支付记录、七日报价人数、纠纷结案率 |
| 财务总览 | 新增近 7/30/90 日支付记录汇总、每日支付记录、全量纠纷退款/发票状态、模拟钱包及提现统计 |
| 提现详情 | 复用模拟钱包审核和事件记录；没有真实打款 |
| 发票审核 | 复用实际发票文件交付；没有自动税务开票 |
| 用户 / 用户详情、订单 / 订单详情 | 复用现有查询、筛选和管理操作；用户ID可复制，供授权管理员使用 |
| 操作日志 | 复用服务端审计列表，新增权限变更与配置变更的中文说明 |
| 权限管理 / 新建账号 | 新增角色列表、对已注册用户的授权、修改角色、停用；不是创建另一套密码账号 |
| 大厅统计 | 新增公开需求供需统计、预算≥5000元的待报价需求数量、浏览 TOP20；排除定向订单 |
| 存储管理 | 新增业务登记文件数量、容量、类型分布及分页清单；不返回云文件ID、网盘密码或任意读取链接 |
| 营销活动 | 新增优惠权益领取汇总，链接现有轮播、活动内容与公告管理；券仍是预留权益，不实际抵扣支付 |
| 平台配置 | 可保存大厅报价热度权重（0–20）；直接影响大厅热门排序及热度显示。其余展示实际运行配置、等级规则，未开放无后端支持的开关 |
| 公告 | 复用定时、角色范围及内容管理 |
| 客服工单列表 / 详情 | 保留“在线会话”和“工单处理”两条入口及原处理流程 |

共用页面 `admin/pages/console/index?kind=...` 承载新模块，避免每个统计页重复实现加载、错误重试及分页。新页面、样式、菜单均在 admin 分包中。原有业务详情页沿用已实现交互，统一页面背景、主色、卡片和按钮样式；未逐像素复刻原型中的演示数据和控件。

## 权限及后端

- 保留超级管理员、运营、审计、身份审核角色，新增仲裁客服、财务角色。
- 账号授权、存储管理、平台配置默认仅超级管理员可访问。财务角色可查看财务、处理发票、操作模拟钱包；不允许分配管理员权限。
- 每次请求服务端核验当前角色。账号变更事务内再次核验操作者，锁定管理员记录，禁止修改自己和部署配置管理的账号，保护有效超级管理员。
- 管理员权限、配置变更与审计日志在同一事务提交。
- 新增 `admin_console_settings` 表，仅保存已经接入后端的大厅权重；启动迁移与 `npm run migrate` 均包含该表。默认权重仍为 3。
- 新增接口统一位于 `/api/admin/console/`：overview、finance、hall、storage、config、marketing、appeals、accounts。写接口仅 config PATCH、accounts POST。

## 数据口径及未接入事项

1. 支付汇总是支付表成功记录，**不是平台净收入或待分账余额**，可能包含历史模拟支付。钱包和提现完全是模拟数据。真实分账、佣金结算、自动打款需支付机构平台产品接入。
2. 文件容量仅为 `uploaded_files` 业务登记，不代表存储桶所有对象用量。自动清理、到期短信、恢复回收站未实现；本次不删除任何文件。
3. 自动信用扣分申诉、税务自动开票、优惠券实际支付抵扣、报表导出及可编辑的等级/佣金规则未实现，不提供虚假成功按钮。
4. 管理员授权要求用户先完成普通账号注册；对方仍使用原有登录方式。没有初始密码短信或强制首次改密流程。
5. 本次未改动原有 14 天自动收货、已确认的身份认证门槛及客服聊天/工单分离规则。

## 部署与验收

1. 部署后端；服务启动会执行幂等迁移，也可在 server 目录运行 `npm run migrate`。
2. 重新编译并发布小程序（包含 admin 分包）。
3. 超级管理员进入工作台，验证待办角标和四个分组；对照数据库核验支付/文件统计。
4. 给测试用户分配审核、仲裁、财务角色，验证入口可见性及无权接口返回 403；停用后刷新应无法继续访问。
5. 修改大厅热度权重，检查热门排序与显示分值；确认日志记录。验证分页、空列表及加载失败重试。
6. 真机确认小屏布局、各审核详情和客服聊天/工单，确认升级未改变原有上传材料流程。

本地可用 Node 回归测试及微信开发者工具 WXML/WXSS 编译器；未连接生产 MySQL，未执行线上授权/配置修改，未完成真机视觉验收。
