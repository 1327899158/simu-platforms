# 黑名单功能

客户和工程师均可在聊天页点击“拉黑”，客户也可从工程师资料页添加。自己的黑名单位于“我的 → 黑名单”，支持分页查看及解除。

## 规则

- 任一方拉黑后，双方不能发起直接咨询、报价咨询，不能在已有会话发送文字、图片或文件（包括订单会话）。服务端校验，不依赖前端按钮。
- 历史消息、已有订单、付款、交付、验收、退款、纠纷、发票和系统通知保留。拉黑不是取消订单或投诉；履约争议仍通过订单及平台处理。
- 本次不隐藏市场订单、工程师推荐和公开案例，也不限制报价或选标，仅限制用户间聊天和发起咨询。
- 只能管理本人拉黑记录；不能拉黑自己、管理员或不存在的用户。互相拉黑时，单方解除不足以恢复聊天。
- 黑名单不通知对方；对方尝试联系时会得到沟通受限提示。正在处理中的并发消息可能在拉黑瞬间完成发送，已发送消息不撤回。

## 部署

先部署后端，再重新编译小程序。后端启动时 `db.init()` 自动创建 `user_blocks`；没有建表权限时，请用有权限的数据库账号执行同目录 `blacklist-table.sql`（单条 SQL，复制时不要包含 Markdown 围栏）。不需要修改现有业务数据。

API：`GET /api/blacklist?offset=0`、`POST /api/blacklist/:id`、`DELETE /api/blacklist/:id`。身份从登录会话获取，不能传入其他 ownerId 代操作。

## 验收步骤

1. 客户进入工程师资料页，点击“加入黑名单”。取消确认不产生记录；确认后“我的 → 黑名单”应出现该工程师。
2. 双方分别进入已有聊天，确认历史消息可见、输入被禁用；尝试直接咨询或报价沟通应失败。直接请求发送接口也应失败。
3. 工程师在聊天页拉黑客户，在自己的黑名单看到客户；客户列表不能看到工程师的其他拉黑记录。
4. 双方互相拉黑后，仅客户解除，仍不可聊天；工程师也解除后刷新会话，恢复原有会话权限（已失效报价会话不会因此重新开放）。
5. 拉黑后验证已有订单仍可交付、验收、申请退款/纠纷，系统通知正常，历史附件仍遵循原有权限。
6. 重复拉黑不产生重复记录；跨账号删除不能解除其他人的拉黑；未登录请求被拒绝。

本地自动测试使用模拟数据库与接口；生产 MySQL 和微信真机需要按上述步骤联调。
