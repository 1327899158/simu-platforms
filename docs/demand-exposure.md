# 需求曝光

普通发布免费。推广仅保留“增加曝光”，每份100位不同工程师、19元，可购买1—100份。在发布表单选择曝光后先创建待支付记录，在订单详情支付；也可为已有待报价的公开需求购买。定向需求不支持公开曝光。

## 展示与人数

- 付费成功后进入已完成身份认证的工程师首页“推荐需求”。每次最多5张，按订单与工程师ID散列分布；普通大厅按最新或热度排序，取消原置顶加急排序和标识。
- 首页卡片至少50%进入屏幕可见区域时上报，隐藏页面停止观察。同一需求对同一工程师账号最多计一次；刷新、重新登录和更换设备不增加重复人数。普通订单浏览量独立统计。
- 展示凭证由服务端签发，绑定需求和工程师，30分钟有效。后端检查工程师身份、订单状态、付款状态、剩余名额及凭证。锁定订单和曝光记录后递增，数据库唯一键防止重复，并发不能超过目标人数。
- 已完成曝光或停止报价的需求不再投放。选标后、关闭后曝光暂停；订单重新进入待报价后可继续剩余名额。没有固定曝光完成时间，实际进度取决于工程师访问首页。
- 客户首页显示“需求正在曝光”，点击进入订单详情。详情展示已推流人数/目标人数、百分比进度条和状态，前台每10秒更新。暂停且未完成时可联系订单客服；未自动退回剩余曝光费。

## 支付与部署

曝光费采用独立 `order_exposures` 支付记录，不与订单服务款、工程师收益或选标金额混合。首次发起支付固定单号、人数和金额，取消支付可重试原单；每个需求当前只支持一笔曝光购买。

真实支付复用已有云托管微信支付开放接口 `unifiedorder` / `queryorder`，回调路径 `/api/exposure-pay/notify`。只有服务端查单核对单号、AppID、商户号、金额、币种及交易流水后才能开通；重复回调不会重复应用。详情查询会查单补偿遗漏的成功通知。

服务端需要已有微信支付配置：`PAYMENT_MODE=wechat`、`WXPAY_MCHID`、`WX_APPID`、云环境ID，及 `WXPAY_CALLBACK_SERVICE`（或平台注入的服务名）。生产收款能力仍取决于对应商户及云托管开放接口已开通。`PAYMENT_MODE=mock` 只用于模拟，客户端明确提示未实际扣款；财务报表分别显示真实实收和模拟支付。

部署新版后端与小程序。后端启动或 `npm run migrate` 会创建 `order_exposures`、`exposure_deliveries`，清除旧 `URGENT` 标记。历史曝光选项此前仅保存选择，没有实际扣款，不自动转为已支付曝光。旧草稿中的置顶加急归为普通发布。

本地测试覆盖服务端计价、所有权、支付归属、回调查单、重复计数、过期凭证、名额并发上限、停止投放和状态进度，以及小程序可见上报、取消支付、模拟确认、进度读取失败与首页跳转。真实云支付、数据库迁移和真机显示需在部署环境验证。
